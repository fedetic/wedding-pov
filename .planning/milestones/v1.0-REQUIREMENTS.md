**Status:** ✅ All requirements shipped and validated

## v1 Requirements — All Complete

### Authentication (AUTH)

- [x] **AUTH-01**: Organizer can create an account with email and password
- [x] **AUTH-02**: Organizer can log in with email and password
- [x] **AUTH-03**: Organizer can connect their Google Drive account via OAuth immediately after signup, before creating their first event

### Event Management (EVENT)

- [x] **EVENT-01**: Organizer can create an event with a name, a configurable photo limit, and an active/inactive toggle
- [x] **EVENT-02**: Organizer can view a list of all their events
- [x] **EVENT-03**: Organizer can toggle an event active or inactive (inactive events reject guest uploads)

### QR Code (QR)

- [x] **QR-01**: Organizer can download a print-ready PNG QR code for any of their events

### Guest Upload (GUEST)

- [x] **GUEST-01**: Guest can open the upload page in a mobile browser by scanning the event QR code — no app install required
- [x] **GUEST-02**: Guest can enter a nickname before uploading photos
- [x] **GUEST-03**: Guest can select up to the event's configured photo limit and initiate an upload
- [x] **GUEST-04**: Guest sees a per-photo progress indicator during upload
- [x] **GUEST-05**: Guest sees a clear completion confirmation when all photos have been uploaded

### Infrastructure (INFRA)

- [x] **INFRA-01**: Photos are uploaded to the organizer's Google Drive into a flat folder named after the event
- [x] **INFRA-02**: Server-side HEIC→JPEG conversion is applied before Drive upload (iOS compatibility)
- [x] **INFRA-03**: Rate limiting is enforced on the guest upload endpoint to prevent abuse (no guest auth)
- [x] **INFRA-04**: Drive uploads use a server-brokered resumable upload pattern — organizer tokens never reach the guest browser

## Out of Scope (Unchanged)

- **Native mobile app** — web app in mobile browser is sufficient; no App Store distribution
- **In-app photo gallery** — organizer views photos directly in Google Drive
- **Per-guest subfolders in Drive** — flat folder keeps implementation simple; Drive search is sufficient
- **Real-time upload dashboard** — organizer monitors uploads via Drive natively
- **Video upload** — file size and Drive quota complexity; not needed for photo-first use case
- **In-app camera** — browser's native file picker surfaces the camera; no custom camera UI needed
- **Billing / SaaS monetization** — v1 is self-serve; monetization is a later milestone
- **Face recognition or AI tagging** — anti-feature; complexity with no proven user demand

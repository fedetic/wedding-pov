    - Native: calls Browser.open() to open the OAuth URL in SFSafariViewController / Chrome Custom Tab
    - Native: listens for appUrlOpen deep link event; when com.weddingpov.app://oauth-callback is received, closes browser and reloads page

    File content (create new):
    ```typescript
    "use client";

    import { Capacitor } from "@capacitor/core";
    import { Browser } from "@capacitor/browser";
    import { App } from "@capacitor/app";
    import { useEffect } from "react";

    interface ConnectDriveButtonProps {
      appUrl: string;
    }

    export function ConnectDriveButton({ appUrl }: ConnectDriveButtonProps) {
      useEffect(() => {
        if (!Capacitor.isNativePlatform()) return;

        const listenerPromise = App.addListener("appUrlOpen", (data) => {
          if (data.url.startsWith("com.weddingpov.app://oauth-callback")) {
            Browser.close().catch(() => {});
            window.location.reload();
          }
        });

        return () => {
          listenerPromise.then((l) => l.remove()).catch(() => {});
        };
      }, []);

      if (Capacitor.isNativePlatform()) {
        return (
          <button
            onClick={async () => {
              await Browser.open({
                url: `${appUrl}/api/drive/connect?mobile=1`,
                presentationStyle: "popover",
              });
            }}
            className="inline-block bg-black text-white rounded px-4 py-2 text-sm font-semibold hover:bg-gray-800"
          >
            Connect Google Drive
          </button>
        );
      }

      return (
        <a
          href="/api/drive/connect"
          className="inline-block bg-black text-white rounded px-4 py-2 text-sm font-semibold hover:bg-gray-800"
        >
          Connect Google Drive
        </a>
      );
    }
    ```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| System browser → Native app | Deep link com.weddingpov.app:// routes from system browser back into the app |
| /api/drive/callback → custom scheme | Server issues 302 to a non-HTTPS URL scheme; intercepted by OS deep link handler |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-04-01 | Spoofing | appUrlOpen deep link handler | mitigate | Handler only reacts to URLs starting with "com.weddingpov.app://oauth-callback" — other app URLs are ignored. No auth token is carried in the deep link URL; reload re-fetches session from the server. |
| T-05-04-02 | Elevation of Privilege | Mobile detection via User-Agent in error path | accept | User-Agent can be spoofed on web; spoofing it causes the server to return a com.weddingpov.app:// redirect instead of a /dashboard redirect — the browser will display a "can't open this URL" page, not a security issue. |
| T-05-04-03 | Tampering | :mobile suffix in AES-256-GCM encrypted state | accept | AES-256-GCM state is unforgeable without ENCRYPTION_KEY. The :mobile suffix only changes the redirect target, not the userId. No security boundary is affected. |
| T-05-04-04 | Information Disclosure | com.weddingpov.app://oauth-callback?success=true URL | accept | No tokens, codes, or user data are in the deep link URL. Success=true is a signal only — the app reloads from the server to learn actual state. |
| T-05-04-SC | Tampering | No new npm installs in this plan | accept | @capacitor/browser and @capacitor/app were installed in Plan 02. No new packages added here. |
</threat_model>

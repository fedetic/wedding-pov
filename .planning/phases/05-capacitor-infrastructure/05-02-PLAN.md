  <action>
    Step 1 — Install Capacitor core and platform packages. Run from project root:

    ```
    npm install @capacitor/core@^8 @capacitor/ios@^8 @capacitor/android@^8
    npm install --save-dev @capacitor/cli@^8
    npm install @capacitor/app@^8 @capacitor/browser@^8
    ```

    All packages must pin to ^8 major. Do not install @capacitor/share or @capacitor/status-bar or @capacitor/splash-screen here — those belong to Phase 6 (native features). Do not install @capacitor/assets here.

    Step 2 — Create capacitor.config.ts at the project root (same level as package.json, next.config.ts):

    ```typescript
    import type { CapacitorConfig } from "@capacitor/cli";

    // server.url points to the live Railway deployment.
    // The app binary is a thin native shell; all SSR, auth, and API calls run on Railway.
    // DO NOT set output: 'export' in next.config.ts — Server Actions and Better Auth cookies
    // are incompatible with static export (per D-01 decision).
    const config: CapacitorConfig = {
      appId: "com.weddingpov.app",
      appName: "Wedding POV",
      webDir: "out", // fallback placeholder — not used when server.url is set
      server: {
        url: process.env.NEXT_PUBLIC_APP_URL ?? "https://wedding-pov-production.up.railway.app",
        cleartext: false, // Railway is HTTPS; no plaintext HTTP allowed
      },
      ios: {
        contentInset: "automatic",
      },
      plugins: {
        // Belt-and-suspenders alongside better-auth-capacitor plugin (Plan 03)
        CapacitorCookies: {
          enabled: true,
        },
      },
    };

    export default config;
    ```

    If the executor finds a .env.local or .env file at project root containing NEXT_PUBLIC_APP_URL=https://..., substitute that value as a string literal instead of the process.env reference (capacitor.config.ts is not a Next.js module and process.env is not guaranteed to be populated at cap-sync time).

    Step 3 — Add mobile scripts to package.json. The scripts section must include these additions alongside the existing scripts:

    ```json
    "cap:sync": "npx cap sync",
    "cap:open:ios": "npx cap open ios",
    "cap:open:android": "npx cap open android"

    Do not remove or modify the existing dev, build, start, lint scripts.

    npx cap add android

    ```

    These commands generate the ios/ and android/ directories. They will take 1–3 minutes each.

    After cap sync, update the iOS Info.plist to declare the Railway domain as a WKAppBoundDomain (per ARCHITECTURE.md — this relaxes WKWebView ITP cookie restrictions for the Railway domain).

    The file to edit is: ios/App/App/Info.plist

    Add the following key-value pair inside the root <dict> of Info.plist, before the closing </dict>:

    ```xml
    <key>WKAppBoundDomains</key>
    <array>
      <string>wedding-pov-production.up.railway.app</string>
    </array>
    ```

    If the actual Railway hostname differs from the placeholder, use the real hostname. The string must be the hostname only (no https:// prefix, no trailing slash, no path).

    Do not add NSAllowsArbitraryLoads to Info.plist (Railway is HTTPS; ATS must remain enabled).

    After ios/ and android/ are generated, add both directories to .gitignore only if they are not already tracked. Convention for Capacitor projects: ios/ and android/ are typically committed (unlike node_modules). Leave them tracked in git.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Native shell → Railway | Thin Capacitor shell making HTTPS calls to Railway; server.url locks the destination |
| cap add / npm install | New packages and generated native project code entering the codebase |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-02-01 | Tampering | capacitor.config.ts server.url | mitigate | cleartext: false ensures HTTPS only; server.url must point to the Railway HTTPS URL, never http:// |
| T-05-02-02 | Elevation of Privilege | WKAppBoundDomains | accept | Declares only the Railway hostname; does not open ITP for all domains. Risk is minimal: ITP relaxation scoped to our own server. |
| T-05-02-03 | Information Disclosure | ios/ and android/ committed to git | accept | Native project directories contain no secrets by default; signing keys are never stored in the project directory |
| T-05-02-SC | Tampering | npm installs (@capacitor/* packages) | mitigate | All packages are from ionic-team official npm scope — high legitimacy confidence. Run `npm audit` after install; block on HIGH/CRITICAL findings. |
</threat_model>

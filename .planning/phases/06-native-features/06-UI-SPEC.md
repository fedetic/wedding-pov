## Spacing Scale

Declared values (all multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline icon-text spacing, badge padding |
| sm | 8px | Compact element spacing, button vertical padding |
| md | 16px | Default element spacing, modal padding, field gap |
| lg | 24px | Section padding, modal card padding |
| xl | 32px | Layout vertical gaps between major sections |
| 2xl | 48px | Page-level top/bottom padding |
| 3xl | 64px | Not used in this phase |

Exceptions:
- Touch targets on native: minimum 44×44px for all tappable elements (biometric toggle, share button, retry button). This exceeds the 8pt scale but is an iOS/Android accessibility requirement.
- Offline overlay: occupies 100% viewport (`inset-0`) — no spacing token applies to the container itself.

Source: Inferred from existing components (`px-4 py-2` = 16px/8px, `p-6` = 24px, `gap-2` = 8px, `gap-4` = 16px) in `QRModal.tsx`, `ConnectDriveButton.tsx`, `DashboardPage`.

## Typography

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Body | 14px | 400 (normal) | 1.5 | Modal body copy, settings descriptions, offline body text |
| Label | 12px | 400 (normal) | 1.4 | Secondary metadata, status captions, toggle state labels |
| Heading | 18px | 600 (semibold) | 1.2 | Settings page section headers, overlay headings |
| Display | 24px | 600 (semibold) | 1.2 | Page-level headings (Settings page `<h1>`) |

Notes:
- Button labels: 14px weight 600 (semibold) — matches existing `text-sm font-semibold` pattern from `QRModal.tsx` and `ConnectDriveButton.tsx`.
- Input labels: 14px weight 500 (medium) — matches `text-sm font-medium` from `SignInForm.tsx`.
- No third or fourth font weight is added. The project uses exactly two weights: 400 and 600. The one `font-medium` instance in forms is acceptable as a minor exception; do not introduce `font-bold` or `font-light`.
- Do not use Geist Mono in any Phase 6 UI — it is available but reserved for code/URL display contexts (the guest URL in QRModal is one exception already in place).

Source: `SignInForm.tsx` (`text-sm font-medium`, `text-2xl font-semibold`), `QRModal.tsx` (`text-base font-semibold`, `text-sm font-normal`, `text-sm font-semibold`), `DashboardPage` (`text-2xl font-semibold`, `text-sm`).

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#ffffff` (white) | Page background, modal background, overlay card background, settings page background |
| Secondary (30%) | `#f9fafb` / Tailwind `gray-50` + `gray-100` | Settings toggle track (disabled state), input borders (`gray-200`), card borders (`gray-200`) |
| Accent (10%) | `#000000` (black) | Primary CTA buttons only, active toggle thumb, biometric lock "Use password" link underline |
| Semantic: Success | `#15803d` / Tailwind `green-700` on `green-50` bg | Drive-connected confirmation (existing pattern — do not introduce new success-colored elements) |
| Semantic: Destructive | `#dc2626` / Tailwind `red-600` on `red-50` bg | Error states only: offline error icon tint, biometric failure text |

Accent reserved for:
1. Primary action buttons (`bg-black text-white`) — "Share QR code", "Save settings", "Retry"
2. Active state of the biometric toggle thumb
3. The "Use password instead" fallback link on the biometric lock screen (underline only, not fill)

Accent is NOT used for:
- Hover states (use `hover:bg-gray-800` — existing pattern)
- Toggle track when enabled (use `bg-black`)
- Any decorative borders or dividers
- The offline overlay background (use `bg-white`)

Offline overlay color note: The overlay sits above the WebView and must be fully opaque white (`bg-white`) — not translucent. The CONTEXT.md describes it as "minimal, on-brand with existing black/white aesthetic."

Source: `globals.css` (`--background: #ffffff`, `--foreground: #171717`), `QRModal.tsx` (`bg-black text-white`, `hover:bg-gray-800`), `ConnectDriveButton.tsx` (`bg-black text-white`), `DashboardPage` (`text-green-700 bg-green-50`, `text-red-700 bg-red-50`).

## Component Inventory

New components required for Phase 6. All follow existing project patterns (manual Tailwind, no external component library).

### 1. Share Button — inside `QRModal.tsx`

- Renders only when `Capacitor.isNativePlatform()` is true
- Positioned: below the Download button, above the Close button (new entry in the `flex flex-col gap-2` actions block)
- Appearance: identical to Download button — `w-full bg-black text-white text-sm font-semibold py-2 px-4 rounded hover:bg-gray-800`
- Label: "Share QR code"
- Disabled state: `disabled:opacity-50 disabled:cursor-not-allowed` when `dataUrl` is null (same as Download)
- Loading state: none required (share sheet is synchronous from user perspective)
- Pattern source: `QRModal.tsx` Download button — duplicate exactly

### 2. Settings Page — `/dashboard/settings`

Layout:
- Same outer shell as dashboard: `min-h-screen px-4 py-6 sm:p-8 max-w-2xl mx-auto`
- Back navigation: `← Dashboard` text link at top-left (14px normal, `text-gray-500 hover:text-black`)
- Page heading: `<h1>` 24px semibold — "Settings"
- One section: `<section>` with `border border-gray-200 rounded-lg p-6` — same card pattern as dashboard sections

Biometric toggle row:
- Horizontal flex row: `flex items-center justify-between`
- Left: label + description in a `flex flex-col gap-1`
  - Label: "Face ID / Touch ID" — 14px semibold
  - Description: "Require biometric authentication on app launch" — 12px normal `text-gray-500`
- Right: toggle switch (custom — see below)
- On non-native (web): entire toggle row hidden via `Capacitor.isNativePlatform()` guard. The page itself is accessible on web — only the toggle row is native-conditional.

Toggle switch:
- Width: 44px, height: 24px (standard iOS-style pill)
- Track enabled: `bg-black rounded-full`
- Track disabled: `bg-gray-200 rounded-full`
- Thumb: `bg-white rounded-full shadow` — 20px diameter, 2px inset
- Transition: `transition-transform duration-150`
- Implemented as a `<button role="switch" aria-checked={enabled}>` — no third-party component
- Touch target: wrapping element must be at minimum 44×44px via padding

### 3. Biometric Lock Screen

- Shown on cold open when biometrics are enabled and the session is valid but biometric confirmation is pending
- Full-screen overlay: `fixed inset-0 bg-white flex flex-col items-center justify-center gap-6 z-50`
- Icon: lock glyph rendered as inline SVG (24×24px, `stroke-[#171717]`, strokeWidth 1.5) — no icon library
- Heading: "Unlock Wedding POV" — 24px semibold, centered
- Body: "Use Face ID or Touch ID to continue" — 14px normal `text-gray-500`, centered, max-width 280px
- Primary button: "Authenticate" — `bg-black text-white text-sm font-semibold py-2 px-6 rounded hover:bg-gray-800`
- Fallback link (appears after 3 consecutive biometric failures): "Use password instead" — 14px normal `text-gray-500 underline hover:text-black`, centered below button
- No close or dismiss affordance — the screen is a gate, not a modal

### 4. Offline Overlay

- Full-screen: `fixed inset-0 bg-white flex flex-col items-center justify-center gap-4 z-50`
- Icon: wifi-off or cloud-slash inline SVG (24×24px, `stroke-[#171717]`, strokeWidth 1.5)
- Heading: "No internet connection" — 18px semibold, centered
- Body: "Check your connection and try again" — 14px normal `text-gray-500`, centered, max-width 280px
- Retry button: "Try again" — `bg-black text-white text-sm font-semibold py-2 px-6 rounded hover:bg-gray-800`
- Reactive: overlay mounts/unmounts based on `@capacitor/network` listener — no page navigation
- The overlay appears on all pages — it lives in `layout.tsx` or a top-level client component wrapper

## Interaction States

| Component | State | Behavior |
|-----------|-------|----------|
| Share button | `dataUrl` null | `disabled` + `opacity-50` — QR not yet generated |
| Share button | Share sheet dismissed | No state change — button remains available |
| Share button | Share API error | Silent fail — do not show error toast (share sheet errors are OS-level) |
| Biometric toggle | Enabling | Immediately trigger biometric prompt to confirm capability; if prompt fails/unavailable, do not enable |
| Biometric toggle | Saving | No loading state needed — preference write is synchronous via `@capacitor/preferences` |
| Biometric lock | Authenticating | Button disabled while prompt is open (no visible spinner needed — OS handles feedback) |
| Biometric lock | Failure (1–2×) | Retry the OS prompt — no in-app feedback |
| Biometric lock | Failure (3×) | Show "Use password instead" fallback link |
| Biometric lock | Fallback tapped | Dismiss overlay; show sign-in form (or navigate to `/login`) |
| Offline overlay | Network lost | Mount overlay with 0ms delay — appears immediately |
| Offline overlay | Network restored | Unmount overlay; do not reload the WebView automatically — wait for "Try again" tap |
| Offline overlay | "Try again" tapped | Check connectivity; if restored, dismiss overlay; if still offline, show brief visual feedback (button text "Checking…" for 1s) |

## Native-Conditional Rendering Pattern

All native-only UI follows the established pattern from `ConnectDriveButton.tsx`:

```
if (Capacitor.isNativePlatform()) {
  // render native variant
}
// render web variant (or null)
```

Apply this pattern to:
- Share button in QRModal: render only on native; web keeps Download-only layout
- Biometric toggle in Settings: render only on native; section is visible but toggle row is hidden on web
- Biometric lock screen: render only on native
- Offline overlay: render on native only (web users have browser offline handling)

Do not use CSS media queries or user-agent sniffing for native detection. `Capacitor.isNativePlatform()` is the sole gate.

## Accessibility

| Requirement | Implementation |
|-------------|----------------|
| Toggle role | `<button role="switch" aria-checked={enabled} aria-label="Face ID / Touch ID">` |
| Offline overlay | `role="alert" aria-live="assertive"` on the overlay container — announced immediately when mounted |
| Biometric lock | `role="dialog" aria-modal="true" aria-label="Biometric authentication required"` |
| Touch target | All interactive elements ≥ 44×44px on native (padding compensates if visual size is smaller) |
| Focus management | Biometric lock screen: focus the "Authenticate" button on mount; offline overlay: focus the "Try again" button on mount |
| Colour contrast | Black (`#000000`) on white (`#ffffff`) — 21:1 ratio. Gray-500 (`#6b7280`) on white — 4.6:1, passes AA for normal text |

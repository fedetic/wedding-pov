<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Railway runtime → Neon | DATABASE_URL transmitted at build/start time; Railway encrypts env vars at rest |
| Public internet → Railway app | All traffic served over HTTPS via Railway's TLS termination |
| GCP redirect → Railway /api/drive/callback | Railway URL must be registered in GCP; unregistered URIs are rejected by Google |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Information Disclosure | Railway env vars | mitigate | Railway dashboard masks secret values in UI; env vars not written to disk or logs |
| T-04-02 | Spoofing | Unregistered redirect URI accepted by GCP | mitigate | GCP only sends callbacks to registered URIs; Task 1 Step D registers the Railway URL explicitly |
| T-04-03 | Elevation of Privilege | OAuth app in Testing mode → 7-day token expiry | accept (flagged) | CRITICAL: GCP app must be promoted to Production before any real event. This is Phase 4 work. Flagged in STATE.md. During dev, add yourself as Test User to avoid 7-day expiry. |
| T-04-04 | Information Disclosure | Secrets in git history | mitigate | .env.local is gitignored (verified in Plan 01); Railway vars injected at runtime, not stored in repo |
| T-04-05 | Denial of Service | Railway free tier cold starts | accept | Single-organizer app; cold starts acceptable for Phase 1; optimize if needed post-launch |
</threat_model>

# 3. Token in Neon

  const { neon } = require('@neondatabase/serverless');
  require('dotenv').config({ path: '.env.local' });
  const sql = neon(process.env.DATABASE_URL);
  Promise.all([
    sql\`SELECT count(*) as c FROM users\`,
    sql\`SELECT count(*) as c FROM google_tokens WHERE encrypted_refresh_token IS NOT NULL\`

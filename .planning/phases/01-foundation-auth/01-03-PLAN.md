<objective>
Implement the custom Google Drive OAuth flow: a connect route that redirects the organizer to Google, and a callback route that exchanges the authorization code for tokens, encrypts the refresh token with AES-256-GCM, and stores it in `google_tokens`.

Purpose: AUTH-03 requires that the organizer can connect Drive before creating their first event. Drive tokens must be encrypted at rest — this is why we use a custom OAuth route instead of Better Auth's `linkSocial` (which would store tokens unencrypted in the `accounts` table).

Output:
- `GET /api/drive/connect` — session-gated, builds Google auth URL, redirects organizer to Google
- `GET /api/drive/callback` — exchanges code for tokens, asserts refresh_token is present, encrypts and UPSERTs into `google_tokens`, redirects to `/dashboard?drive=connected`
- GCP OAuth credentials added to `.env.local`
</objective>

**Step 1 — Create `src/app/api/drive/connect/route.ts`:**

Create directory `src/app/api/drive/connect/` first.

```typescript
import { NextRequest, NextResponse } from "next/server";
import { auth } from "@/lib/auth";
import { headers } from "next/headers";
import { google } from "googleapis";

export async function GET(request: NextRequest) {
  // Session guard — must be logged in to connect Drive
  const session = await auth.api.getSession({ headers: await headers() });
  if (!session) {
    return NextResponse.redirect(new URL("/login", request.url));
  }

  const oauth2Client = new google.auth.OAuth2(
    process.env.GOOGLE_CLIENT_ID!,
    process.env.GOOGLE_CLIENT_SECRET!,
    // Redirect URI — must exactly match a URI registered in GCP Console
    `${process.env.BETTER_AUTH_URL}/api/drive/callback`,
  );

  const authUrl = oauth2Client.generateAuthUrl({
    access_type: "offline",              // request refresh token
    prompt: "select_account consent",   // force consent screen to always get refresh token
    scope: ["https://www.googleapis.com/auth/drive.file"], // ONLY drive.file — never use drive scope
    state: session.user.id,             // carry userId through the OAuth round-trip
  });

  return NextResponse.redirect(authUrl);
}
```

**CRITICAL scope note:** The scope is `https://www.googleapis.com/auth/drive.file` — NOT `https://www.googleapis.com/auth/drive`. The full `drive` scope triggers a weeks-long Google security review. `drive.file` only allows the app to see files it created.

**CRITICAL prompt note:** `prompt: "select_account consent"` forces Google to show the consent screen even if the user previously authorized. This is the only way to guarantee a fresh `refresh_token` on every connect attempt.

**Step 2 — Create `src/app/api/drive/callback/route.ts`:**

Create directory `src/app/api/drive/callback/` first.

```typescript
import { NextRequest, NextResponse } from "next/server";
import { google } from "googleapis";
import { db } from "@/lib/db";
import { googleTokens } from "@/lib/db/schema";
import { encrypt } from "@/lib/crypto";
import { eq } from "drizzle-orm";
import { randomUUID } from "crypto";

export async function GET(request: NextRequest) {
  const { searchParams } = new URL(request.url);
  const code = searchParams.get("code");
  const userId = searchParams.get("state"); // set in connect route
  const error = searchParams.get("error");

  // Handle user-denied or error from Google
  if (error || !code || !userId) {
    console.error("[drive/callback] OAuth error or missing params:", { error, hasCode: !!code, hasUserId: !!userId });
    return NextResponse.redirect(new URL("/dashboard?drive=error", request.url));
  }

  const oauth2Client = new google.auth.OAuth2(
    process.env.GOOGLE_CLIENT_ID!,
    process.env.GOOGLE_CLIENT_SECRET!,
    `${process.env.BETTER_AUTH_URL}/api/drive/callback`, // must match connect route exactly
  );

  let tokens: Awaited<ReturnType<typeof oauth2Client.getToken>>["tokens"];
  try {
    const result = await oauth2Client.getToken(code);
    tokens = result.tokens;
  } catch (e) {
    console.error("[drive/callback] Token exchange failed:", e);
    return NextResponse.redirect(new URL("/dashboard?drive=error", request.url));
  }

  // CRITICAL: assert refresh_token is present
  // Google only issues refresh_token on FIRST consent. If null here, the user previously
  // connected and the token wasn't stored. Re-trigger with forced consent.
  if (!tokens.refresh_token) {
    console.warn("[drive/callback] refresh_token is null — re-triggering consent flow");
    const retryUrl = new URL("/api/drive/connect", request.url);
    return NextResponse.redirect(retryUrl);
  }

  // Encrypt the refresh token before storing — AES-256-GCM via ENCRYPTION_KEY
  const encryptedRefreshToken = encrypt(tokens.refresh_token);

  // UPSERT: one row per organizer (unique constraint on userId)
  await db
    .insert(googleTokens)
    .values({
      id: randomUUID(),
      userId,
      encryptedRefreshToken,
      accessToken: tokens.access_token ?? null,
      accessTokenExpiresAt: tokens.expiry_date
        ? new Date(tokens.expiry_date)
        : null,
    })
    .onConflictDoUpdate({
      target: googleTokens.userId,
      set: {
        encryptedRefreshToken,
        accessToken: tokens.access_token ?? null,
        accessTokenExpiresAt: tokens.expiry_date
          ? new Date(tokens.expiry_date)
          : null,
        updatedAt: new Date(),
      },
    });

  console.info("[drive/callback] Drive connected for userId:", userId);
  return NextResponse.redirect(new URL("/dashboard?drive=connected", request.url));
}
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| /api/drive/connect → Google OAuth | Server builds auth URL; client only follows the redirect — credentials never reach browser |
| Google OAuth → /api/drive/callback | Authorization code arrives via redirect; server exchanges for tokens — tokens never reach browser |
| App → google_tokens DB column | Refresh token stored AES-256-GCM encrypted; raw token never written to DB |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Spoofing | CSRF on /api/drive/callback | mitigate | `state` parameter carries `session.user.id`; callback validates it is non-null. Full CSRF protection (state signature) is a Phase 4 hardening — acceptable for single-organizer dev phase |
| T-03-02 | Information Disclosure | refresh_token in plaintext | mitigate | `encrypt(tokens.refresh_token)` called before any DB write; raw token only exists in memory during callback execution |
| T-03-03 | Tampering | Encrypted refresh_token in DB | mitigate | AES-256-GCM `decrypt()` throws `ERR_CRYPTO_GCM_AUTH_FAILED` if authTag doesn't match — detects any tampering attempt |
| T-03-04 | Spoofing | Drive connected with wrong userId | mitigate | `state` parameter carries the session user ID; callback binds the token row to that exact userId via UPSERT target |
| T-03-05 | Denial of Service | Missing refresh_token causes infinite retry loop | mitigate | Callback re-triggers `/api/drive/connect` (not itself); `prompt: "select_account consent"` on re-trigger forces new consent that yields a fresh refresh_token |
| T-03-06 | Privilege Escalation | drive scope (full Drive access) | mitigate | Scope locked to `https://www.googleapis.com/auth/drive.file`; this is enforced in generateAuthUrl() and should be verified in GCP consent screen during Task 1 |
</threat_model>

## Part B — Rate Limit Spot-Check (Optional but Recommended)

This verifies the abuse protection is working on Production. You need a terminal with `curl`.

```bash
# Replace [slug] with your active event slug
# Replace /path/to/photo.jpg with any small JPEG
SLUG="your-event-slug"
PHOTO="/path/to/small.jpg"
BASE_URL="https://wedding-pov-production.up.railway.app"

# Upload 31 photos in a loop (limit is 30 per 15 minutes per IP)
for i in $(seq 1 31); do
  STATUS=$(curl -s -o /dev/null -w "%{http_code}" \
    -X POST "$BASE_URL/api/upload/$SLUG" \
    -F "nickname=RateTest" \
    -F "file=@$PHOTO")
  echo "Upload $i: HTTP $STATUS"
done
```

Expected output:
- Uploads 1–30: `HTTP 200`
- Upload 31: `HTTP 429` (with `Retry-After` header)

If upload 31 returns 200, the rate limiter is not working as expected on Production — note it.

> **Note:** If you ran uploads in Tasks 1 and 2 from the same IP, those uploads count toward the rate limit. The counter resets after 15 minutes. Run this test from the same IP you used for Task 1 to get a clean count, or wait for the window to reset.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Guest browser → /api/upload/[slug] | Unauthenticated — any party with the URL can POST. Rate limiting and isActive check are the primary controls. |
| Drive folder | Only files created by this app appear in the event folder (drive.file scope). Guests cannot read, modify, or delete other files. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-05 | Denial of Service | /api/upload/[slug] | mitigate | RateLimiterMemory: 30 uploads per 15 min per IP:slug. Verified in Part B of Task 3. |
| T-04-06 | Spoofing | Inactive event bypass | mitigate | API returns 404 for isActive=false events (not 403 — no slug enumeration leak). Verified in Task 2 Part B. |
| T-04-07 | Information Disclosure | Drive file visibility | accept | Drive files are in organizer's personal Drive. Only organizer has Drive access. Guests get no Drive URLs in API responses (only driveFileId is returned, not a public link). |
| T-04-08 | Tampering | HEIC conversion output | accept | heic-convert is a well-maintained library. Converted files are written to Drive as JPEG — organizer can visually verify. |
</threat_model>

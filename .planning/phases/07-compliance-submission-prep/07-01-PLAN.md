```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
  <key>NSPrivacyTracking</key>
  <false/>

      <key>NSPrivacyAccessedAPITypeReasons</key>
      <array>
        <string>CA92.1</string>
      </array>
    </dict>
  </array>
</dict>
</plist>
```

Rationale for the chosen API/reason set:
- `NSPrivacyTracking = false`: app does no cross-app/cross-site user tracking
- `NSPrivacyTrackingDomains = []`: no domains contacted that perform tracking
- `NSPrivacyCollectedDataTypes = []`: per the privacy policy, we collect organizer email + uploaded photos, but at the app process level we do not record these in a way that fits Apple's collected-data taxonomy (data is sent directly to our own backend, not aggregated/transmitted as analytics)
- `NSPrivacyAccessedAPICategoryUserDefaults` with reason `CA92.1`: `@capacitor/preferences` writes to `NSUserDefaults` (biometric toggle, session persistence cache) — reason CA92.1 = "Access info from same app, per documentation"
- No other plugin in the dependency set (`@capacitor/filesystem`, `@capacitor/network`, `@capacitor/share`, `@capacitor/browser`, `@capacitor/app`, `@aparajita/capacitor-biometric-auth`) uses a required-reason API per the audit in research

After file creation, run `npx cap sync ios` to refresh the Xcode project state.

NOTE: This task ONLY creates the file. Adding it to the Xcode project target (project.pbxproj reference) is the human checkpoint in Task 3 — see Pitfall 2 in research: the file on disk alone is insufficient.</action>

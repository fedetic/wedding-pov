**Step A — Confirm middleware does not block /e/* :**

```bash
grep -n "matcher" src/middleware.ts
```

Expected output: `matcher: ["/dashboard/:path*"]`

The middleware already uses a narrow matcher. `/e/[slug]` is NOT protected. No changes needed.

**If** the matcher somehow includes `/e/` or a broad pattern like `/((?!api|_next).*)/`, update it to only match `/dashboard/:path*`. Do not add `/e/` to any exclusion list — exclusion lists are fragile; the matcher-whitelist approach is already correct.

**Step B — Confirm page is at correct (public) path:**

```bash
test -f src/app/e/\[slug\]/page.tsx && echo "PASS: page at correct path"
test ! -f src/app/\(organizer\)/e/\[slug\]/page.tsx && echo "PASS: not in organizer group"
test ! -f src/app/\(auth\)/e/\[slug\]/page.tsx && echo "PASS: not in auth group"
```

All three must print PASS.

**Step C — Full production build:**

```bash
npm run build 2>&1 | tail -30
```

Fix any TypeScript or import errors that surface. Common issues to watch for:
- `heic-convert` type declarations missing → add `declare module 'heic-convert'` in `src/types/heic-convert.d.ts` if needed
- `Readable` import from 'stream' may need `import type` adjustment — if build fails on `Readable`, change to `import { Readable } from 'node:stream'`
- `rate-limiter-flexible` types — installed automatically with the package

Build must complete with status 0 and show the `/e/[slug]` route in the build output.


1. Ensure an event exists in your local/staging DB with `is_active = true` and a valid `drive_folder_id`

3. Note the event's `slug` value

**Mobile test (preferred — primary use case):**
1. Start the dev server: `npm run dev`
2. Find your local IP: `ipconfig getifaddr en0` (Mac) — result e.g. `192.168.1.42`
3. On your iPhone, open Safari and navigate to `http://192.168.1.42:3000/e/{slug}`
4. Confirm: event name appears with terracotta accent rule below it
5. Enter a nickname → tap "Continue →" → confirm you advance to Step 2
6. Tap "Select photos" → photo library opens (NOT camera-only) → select 2-3 photos including at least one HEIC if possible
7. Confirm photo list shows thumbnails + filenames; count shown as "N of {limit} photos selected"
8. Tap "Upload N photos →" → progress bars appear per photo, advancing as each uploads
9. After all complete → "You're all done! 🎉" screen appears
10. Open Google Drive on desktop → navigate to the event's folder → confirm photos appear named as `{nickname}_001.jpg`, `{nickname}_002.jpg`, etc.
11. Confirm HEIC photos are stored as JPEG (check file extension and MIME type in Drive)

**Desktop test (secondary):**
1. Navigate to `http://localhost:3000/e/{slug}` in Chrome
2. Complete the same flow with a regular JPEG from your filesystem
3. Confirm the upload record appears in the `upload_records` DB table

**Rate limit test (optional):**
